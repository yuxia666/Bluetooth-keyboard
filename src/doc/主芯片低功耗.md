# 主芯片低功耗（CAF Power Manager + 真实按键唤醒）

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.1 |
| 编制日期 | 2026-08-31 |
| 适用工程 | `01_code` |
| 前置依赖 | CAF / app_event_manager / 矩阵按键 / IP5306 keepalive |
| 状态 | 已实现，编译验证通过 |

---

## 1. 目标

基于 CAF Power Manager 实现主芯片真实低功耗与按键唤醒：

- 使用 `app_event_manager` 作为事件总线。
- 启用 CAF Power Manager。
- 系统空闲后自动进入低功耗 **suspended** 状态，不进入 System OFF。
- 低功耗时 main 线程真正阻塞，CPU 可进入 idle。
- 按键按下时通过矩阵 GPIO 中断唤醒系统。
- 唤醒后发送 `wake_up_event`，退出低功耗。
- 正常状态按键发送 `keep_alive_event`，防止进入低功耗。

## 2. 整体架构

```text
CAF Power Manager
   │
   │ 空闲超时后发送 power_down_event
   ▼
power_state_logger.c
   │
   │ 打印 enter low power
   │ 维护 suspended 状态
   ▼
matrix.c
   │
   │ 进入低功耗唤醒模式：
   │   行 = 输出高
   │   列 = 输入 + 下拉 + 上升沿中断
   ▼
main 线程阻塞等待唤醒信号量
   │
按键按下 → 对应列被拉高 → 列 GPIO 中断
   │
   ▼
k_sem_give()
   │
   ▼
main 恢复 -> matrix_resume()
   │
   ├─ 恢复矩阵 GPIO 配置
   ├─ 提交 wake_up_event
   ▼
power_state_logger.c
   │
   │ 打印 exit low power
   ▼
恢复矩阵扫描 / 恢复 battery_module
```

所有模块之间通过 `app_event_manager` 事件总线通信。

## 3. 事件流说明

### 3.1 进入低功耗

1. 系统启动后，`main` 上报 `MODULE_STATE_READY`。
2. CAF Power Manager 启动空闲计时。
3. 空闲时间达到 `CONFIG_CAF_POWER_MANAGER_TIMEOUT` 后，发送 `power_down_event`。
4. `power_state_logger` 置 `suspended = true`，打印：

   ```text
   enter low power
   ```

5. `matrix.c` 收到 `power_down_event` 后进入唤醒模式：

   ```text
   行：输出高
   列：输入 + 内部下拉 + 上升沿中断
   ```

6. `battery_module` 取消 8 秒周期任务。
7. main 检测到 `matrix_is_suspended()` 后阻塞在唤醒信号量上。
8. CPU 进入 idle，实现真实低功耗。

### 3.2 按键唤醒（真实低功耗链路）

1. 低功耗状态下，用户按下任意按键。
2. 行输出高电平通过按键把对应列拉高。
3. 列 GPIO 上升沿中断触发。
4. 中断处理函数中 `k_sem_give(&matrix_wake_sem)`。
5. main 线程被唤醒，调用 `matrix_resume()`：
   - 恢复矩阵正常 GPIO 配置；
   - 提交 `wake_up_event`。
6. Power Manager 收到 `wake_up_event`，退出 suspended。
7. `power_state_logger` 打印：

   ```text
   exit low power
   ```

8. main 继续矩阵扫描，识别具体按键并产生 `button_event`。

### 3.3 正常状态保活

1. 系统未进入低功耗时按键按下。
2. 矩阵扫描产生 `button_event`。
3. `button_wake` 检测到 `suspended == false`，发送 `keep_alive_event`。
4. Power Manager 重置空闲计时器，系统不会马上进入低功耗。

## 4. 真实低功耗关键设计

### 4.1 为什么矩阵要反转驱动方向

正常扫描时：

```text
行 = 输入 + 下拉
列 = 输出高，逐列扫描
```

如果低功耗时继续这种模式，main 必须持续轮询，无法真正睡眠。

低功耗唤醒模式改为：

```text
行 = 全部输出高
列 = 输入 + 内部下拉 + 上升沿中断
```

这样任意按键按下都会把对应列拉高，产生 GPIO 中断，不需要 CPU 轮询。

### 4.2 main 线程阻塞

```c
while (1) {
    if (matrix_is_suspended()) {
        /* 真正低功耗：main 阻塞，等待 GPIO 中断唤醒 */
        matrix_wait_wake();
        matrix_resume();
    } else {
        matrix_scan();
        k_msleep(5);
    }
}
```

进入低功耗后，main 不再每 5ms 轮询，而是阻塞在信号量上。

### 4.3 中断只负责唤醒

```c
static void col_wake_isr(...)
{
    /* 只唤醒 main 线程，按键识别交给恢复后的扫描 */
    k_sem_give(&matrix_wake_sem);
}
```

具体是哪个按键，等恢复扫描后再通过 `button_event` 识别。

### 4.4 恢复并提交 wake_up_event

```c
void matrix_resume(void)
{
    if (suspended) {
        matrix_exit_suspend();
    }

    APP_EVENT_SUBMIT(new_wake_up_event());
}
```

先恢复 GPIO，再通知电源管理退出低功耗。

### 4.5 battery_module 挂起/恢复

- 收到 `power_down_event`：取消 8 秒周期任务。
- 收到 `wake_up_event`：恢复 8 秒周期任务。

避免低功耗期间被电池读取任务周期性唤醒。

## 6. Kconfig 配置

```conf
# CAF 事件管理器
CONFIG_CAF=y
CONFIG_APP_EVENT_MANAGER=y
CONFIG_CAF_BUTTON_EVENTS=y

# CAF Power Manager
CONFIG_CAF_POWER_MANAGER=y
CONFIG_CAF_POWER_MANAGER_STAY_ON=y
CONFIG_CAF_POWER_MANAGER_TIMEOUT=10
CONFIG_CAF_KEEP_ALIVE_EVENTS=y

# 系统
CONFIG_REBOOT=y
CONFIG_HEAP_MEM_POOL_SIZE=4096
```

说明：

| 配置 | 作用 |
| --- | --- |
| `CONFIG_CAF_POWER_MANAGER` | 启用 CAF 电源管理 |
| `CONFIG_CAF_POWER_MANAGER_STAY_ON` | 禁止进入 System OFF，只保持 suspended |
| `CONFIG_CAF_POWER_MANAGER_TIMEOUT` | 空闲多少秒后进入低功耗，默认示例为 10 秒 |
| `CONFIG_CAF_KEEP_ALIVE_EVENTS` | 启用 keep alive 事件 |
| `CONFIG_REBOOT` | 提供 `sys_reboot`，CAF Power Manager 链接需要 |
| `CONFIG_HEAP_MEM_POOL_SIZE` | app_event_manager 动态分配需要堆内存 |

## 7. 核心代码逻辑

### 7.1 power_state_logger.c

```c
static bool power_suspended;

bool power_state_is_suspended(void)
{
    return power_suspended;
}

static bool handle_power_down_event(const struct power_down_event *evt)
{
    power_suspended = true;
    printk("enter low power\n");
    return false;
}

static bool handle_wake_up_event(const struct wake_up_event *evt)
{
    if (power_suspended) {
        power_suspended = false;
        printk("exit low power\n");
    }
    return false;
}
```

### 7.2 matrix.c 低功耗唤醒

```c
static void matrix_enter_suspend(void)
{
    /* 行全部输出高 */
    for (int i = 0; i < ROW_COUNT; i++) {
        gpio_pin_configure_dt(&rows[i], GPIO_OUTPUT_ACTIVE);
    }

    /* 列改为输入 + 下拉 + 上升沿中断 */
    for (int i = 0; i < COL_COUNT; i++) {
        gpio_init_callback(&col_wake[i].cb, col_wake_isr, BIT(cols[i].pin));
        gpio_add_callback(cols[i].port, &col_wake[i].cb);
        gpio_pin_configure_dt(&cols[i], GPIO_INPUT | GPIO_PULL_DOWN);
        gpio_pin_interrupt_configure_dt(&cols[i], GPIO_INT_EDGE_RISING);
    }

    suspended = true;
}
```

### 7.3 button_wake.c

```c
static bool handle_button_event(const struct button_event *evt)
{
    if (!evt->pressed) {
        return false;
    }

    if (power_state_is_suspended()) {
        APP_EVENT_SUBMIT(new_wake_up_event());
    } else {
        keep_alive();
    }

    return false;
}
```

> 说明：在真实低功耗链路中，`button_event` 是唤醒恢复扫描后才产生的。  
> 唤醒本身由矩阵列 GPIO 中断完成，`wake_up_event` 由 `matrix_resume()` 提交。  
> `button_wake` 主要负责正常状态下的 keep alive 保活。

## 8. 预期 RTT 日志

```text
矩阵按键扫描已启动
...
[10 秒无操作]
enter low power

[按下任意按键]
exit low power
[0,3]旋钮按键
```

- 低功耗状态下按键：先 `exit low power`，随后正常按键打印。
- 正常状态下按键：不打印 `exit low power`，只打印按键信息，同时发送 `keep_alive_event` 重置空闲计时。

## 10. GPIOTE 通道占用

当前低功耗唤醒和硬件外设占用：

| 功能 | GPIOTE 通道数 |
| --- | --- |
| 矩阵 6 行唤醒中断 | 6 |
| 编码器 A/B | 2 |
| IP5306 keepalive（RTC 中断，不占 GPIOTE） | 0 |
| 合计 | 8 |

nRF52840 共有 8 个 GPIOTE 通道，当前已刚好用满。

后续如果新增中断引脚，需要评估：

- 后续新增中断前需重新规划 GPIOTE 通道；
- 当前 keepalive 不占用 GPIOTE，矩阵 6 行唤醒 + 编码器 2 共占用 8/8。

## 11. 注意事项

1. 当前已实现**真实低功耗**：低功耗时 main 阻塞，battery_module 挂起，CPU 可进入 idle。
2. IP5306 keepalive 由 RTC2 中断产生，不依赖线程定时器；P0.22 在 RTC 中断中直接拉低/拉高。
3. `CONFIG_CAF_POWER_MANAGER_TIMEOUT=10` 便于测试，量产时可调整。
4. 当前 GPIOTE 使用 8/8（矩阵 6 行 + 编码器 2），后续新增中断前必须重新规划。
5. 低功耗唤醒中断使用上升沿；如果按键在进入低功耗前已被按住，需要改为电平触发或先释放再按下才能唤醒。
