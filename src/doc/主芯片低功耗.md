| 项目 | 内容 |
| --- | --- |

| 适用工程 | `01_code` |
| 前置依赖 | CAF / app_event_manager / 矩阵按键 `button_event` |

---

## 1. 目标

基于 CAF Power Manager 实现主芯片低功耗与按键唤醒：

- 使用 `app_event_manager` 作为事件总线。
- 启用 CAF Power Manager。
- 系统空闲后自动进入低功耗 **suspended** 状态，不进入 System OFF。
- 按键按下时：
  - 当前处于低功耗状态 → 发送 `wake_up_event`
  - 当前未处于低功耗状态 → 发送 `keep_alive_event`
- `power_state_logger.c` 监听 `power_down_event` 和 `wake_up_event`：
  - 进入低功耗打印 `enter low power`
  - 退出低功耗打印 `exit low power`

---

## 2. 架构

```text
CAF Power Manager
   │
   │ 空闲超时后发送 power_down_event
   ▼
power_state_logger.c
   │
   │ 打印 enter low power
   │ 维护 suspended 状态
   ▼
按键按下 → button_event
   │
   ├─ suspended 状态？ → 发送 wake_up_event
   │
   └─ 非 suspended 状态？ → 发送 keep_alive_event
   ▼
power_state_logger.c
   │
   │ 收到 wake_up_event
   ▼
打印 exit low power
```

所有模块之间通过 `app_event_manager` 事件总线通信，模块之间不直接调用。

---

## 3. 事件流说明

### 3.1 进入低功耗

1. 系统启动后，`main` 上报 `MODULE_STATE_READY`。
2. CAF Power Manager 启动空闲计时。
3. 空闲时间达到 `CONFIG_CAF_POWER_MANAGER_TIMEOUT` 后，Power Manager 发送 `power_down_event`。
4. `power_state_logger` 收到事件，置 `suspended = true`，打印：

   ```text
   enter low power
   ```

5. 由于配置了 `CONFIG_CAF_POWER_MANAGER_STAY_ON=y`，系统只进入 suspended，不进入 System OFF。

### 3.2 按键唤醒

1. 低功耗状态下按键按下，矩阵扫描产生 `button_event`。
2. `button_wake` 模块检测到当前 `suspended == true`，发送 `wake_up_event`。
3. Power Manager 处理 `wake_up_event`，系统退出 suspended。
4. `power_state_logger` 收到 `wake_up_event`，打印：

   ```text
   exit low power
   ```

### 3.3 正常状态保活

1. 系统未进入低功耗时按键按下，产生 `button_event`。
2. `button_wake` 模块检测到 `suspended == false`，发送 `keep_alive_event`。
3. Power Manager 重置空闲计时器，系统不会马上进入低功耗。

## 5. Kconfig 配置

```conf
# CAF 事件管理器
CONFIG_CAF=y
CONFIG_APP_EVENT_MANAGER=y
CONFIG_CAF_BUTTON_EVENTS=y

# CAF Power Manager
CONFIG_CAF_POWER_MANAGER=y
CONFIG_CAF_POWER_MANAGER_STAY_ON=y
CONFIG_CAF_POWER_MANAGER_TIMEOUT=10
CONFIG_CAF_KEEP_ALIVE_EVENTS=y

# 系统
CONFIG_REBOOT=y
CONFIG_HEAP_MEM_POOL_SIZE=4096
```

说明：

| 配置 | 作用 |
| --- | --- |
| `CONFIG_CAF_POWER_MANAGER` | 启用 CAF 电源管理 |
| `CONFIG_CAF_POWER_MANAGER_STAY_ON` | 禁止进入 System OFF，只保持 suspended |
| `CONFIG_CAF_POWER_MANAGER_TIMEOUT` | 空闲多少秒后进入低功耗，默认示例为 10 秒 |
| `CONFIG_CAF_KEEP_ALIVE_EVENTS` | 启用 keep alive 事件 |
| `CONFIG_REBOOT` | 提供 `sys_reboot`，CAF Power Manager 链接需要 |
| `CONFIG_HEAP_MEM_POOL_SIZE` | app_event_manager 动态分配需要堆内存 |

## 6. 核心代码逻辑

### 6.1 power_state_logger.c

```c
static bool power_suspended;

bool power_state_is_suspended(void)
{
    return power_suspended;
}

static bool handle_power_down_event(const struct power_down_event *evt)
{
    power_suspended = true;
    printk("enter low power\n");
    return false;
}

static bool handle_wake_up_event(const struct wake_up_event *evt)
{
    if (power_suspended) {
        power_suspended = false;
        printk("exit low power\n");
    }
    return false;
}
```

### 6.2 button_wake.c

```c
static bool handle_button_event(const struct button_event *evt)
{
    if (!evt->pressed) {
        return false;
    }

    if (power_state_is_suspended()) {
        APP_EVENT_SUBMIT(new_wake_up_event());
    } else {
        keep_alive();
    }

    return false;
}
```

## 7. 预期 RTT 日志

```text
矩阵按键扫描已启动
...
[10 秒无操作]
enter low power

[按下任意按键]
exit low power
[0,3]旋钮按键
```

- 低功耗状态下按键：先 `exit low power`，随后正常按键打印。
- 正常状态下按键：不打印 `exit low power`，只打印按键信息，同时发送 `keep_alive_event` 重置空闲计时。

## 9. 注意事项

1. 当前实现为**事件级低功耗**：CAF Power Manager 会进入 suspended 状态并打印日志，矩阵扫描仍保持轮询，确保按键事件能产生。
2. 如果后续需要真正进入 CPU 深度睡眠并靠 GPIO 中断唤醒，需要在 `matrix.c` 中增加：
   - 低功耗时将所有列拉高；
   - 行 GPIO 配置为上升沿中断；
   - 中断中发送 `wake_up_event` 并唤醒主扫描循环。
3. 当前 `CONFIG_CAF_POWER_MANAGER_TIMEOUT=10` 便于测试，量产时可调整为实际需求。
