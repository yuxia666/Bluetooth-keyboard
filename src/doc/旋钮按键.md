# 旋钮（EC11 编码器）方向与卡点显示方案

> 修订版 V1.1（2026-08-31）
> 本版对照 `src/doc/编码器.md` 进行修改，采用其中的 `gpio-qdec` 方案、NFC UICR 禁用方式、事件桥接思路与 RTT 打印格式。
> 当前状态：**路线 B 代码已编写，编译验证通过；烧录由用户自行执行**。

---

## 0. 结论摘要

1. 采用 Zephyr 现成驱动 **`gpio-qdec`**（compatible `gpio-qdec`），不重复造轮子。
2. 本项目的矩阵按键目前实现在 `src/main.c` 中，与参考文档的 `src/app/matrix.c` / `keymap.c` 架构不同，因此需要先确定“最小适配”还是“对齐参考架构”。
3. NFC 禁用使用新机制：`&uicr { nfct-pins-as-gpios; };`。
4. EC11：20 卡点 / 圈 = 80 步 / 圈，1 卡点 = 4 步。
5. `steps-per-period = <4>` 后，驱动每转过 1 个卡点上报 1 次事件，事件值 ±1 即卡点数。
6. RTT 打印格式：
   ```
   旋钮旋转 顺时针 1 卡点 (本次 +18°, 累计 +18°)
   旋钮旋转 逆时针 1 卡点 (本次 -18°, 累计 0°)
   ```

---

## 1. 与 `编码器.md` 对照后的关键修改点

### 1.1 采用 `gpio-qdec`，放弃“硬件 QDEC 外设”方案

参考文档明确采用 `gpio-qdec`，理由：

- Zephyr 自带正交解码、消抖、空闲中断唤醒；
- `steps-per-period = <4>` 天然把“80 步/圈”折算成“20 卡点/圈”；
- CAF 无现成编码器模块，但自定义桥接层工作量小。

因此本方案后续以 `gpio-qdec` 为主，不再推荐 nRF52840 硬件 QDEC 外设。

### 1.2 NFC 禁用方式

参考文档已核实：旧 Kconfig 符号 `CONFIG_NFCT_PINS_AS_GPIOS` 在本 SDK 已移除，新机制是板级 DTS 写 UICR：

```dts
&uicr {
	nfct-pins-as-gpios;
};
```

作用：将 nRF52 的 NFC 引脚 **P0.09 / P0.10** 释放为普通 GPIO。
本项目 EC11A 使用 P0.10（NFC2），所以必须添加此属性。

### 1.3 输出格式与累计角度

按参考文档已确认格式：

```text
旋钮旋转 顺时针 1 卡点 (本次 +18°, 累计 +18°)
旋钮旋转 逆时针 1 卡点 (本次 -18°, 累计 0°)
```

- 角度换算：`角度 = 卡点数 × 18°`
- 累计角度：模块内 `int32_t` 累计，重启清零，仅用于 RTT 显示。

## 2. 当前工程与参考文档的差异

| 项目 | 参考文档 `编码器.md` | 当前 `01_code` |

因此不能照搬参考文档文件路径，需要做以下适配。

## 3. 实施路线（已确认：先 A 后 B）

### 路线 A：最小适配（推荐先做验证）✅ 当前阶段先执行

保留现有 `src/main.c` 矩阵扫描，只增加编码器：

1. 在 board DTS / overlay 增加 `encoder` 节点（`gpio-qdec`）。
2. 在 board DTS 增加 `&uicr { nfct-pins-as-gpios; };`。
3. `prj.conf` 增加 `CONFIG_INPUT=y`。
4. 在 `main.c` 或新增 `src/encoder.c` 中使用 `INPUT_CALLBACK_DEFINE` 接收 `INPUT_REL_WHEEL`。
5. 收到事件后直接 RTT 打印方向、卡点数、本次/累计角度。
6. 修改 `CMakeLists.txt` 加入新源文件（如新增 `src/encoder.c`）。

优点：

- 不动现有矩阵扫描逻辑；
- 改动最小，最快验证编码器硬件；
- 不需要引入 CAF / `encoder_event`。

缺点：

- 与参考文档的“事件桥接 + keymap 消费”架构不一致；
- 后续如果要做 HID 音量/滚动，需要在打印处改为事件上报。

### 路线 B：对齐参考架构（后续扩展更顺）✅ 硬件验证通过后重构

按 `编码器.md` 的架构改造：

1. 新建 `src/app/encoder_event.h` / `src/app/encoder_event.c`，自定义 `encoder_event`。
2. 新建 `src/app/encoder.c`，订阅 `gpio-qdec` 的 `INPUT_REL_WHEEL`，转成 `encoder_event`。
3. 新建 `src/app/keymap.c`，订阅 `encoder_event` 并 RTT 打印。
4. 将现有 `src/main.c` 中的矩阵扫描逐步整理为 `src/app/matrix.c` + `keymap.c`（如需完全对齐 P1 架构）。
5. 修改 `CMakeLists.txt` 加入上述源文件。
6. `prj.conf` 增加 `CONFIG_INPUT=y`；若走 CAF 事件，还需要引入 `CONFIG_CAF` / `APP_EVENT_MANAGER` 等。

优点：

- 与 `编码器.md` 完全一致；
- 后续音量、滚动、Fn 层等可直接复用 `encoder_event`。

缺点：

- 需要较大范围重构现有矩阵实现；
- 会改动当前已工作的矩阵按键代码。

## 4. DTS 修改点（以 board DTS 为例）

在 `boards/LZA/DEMO01_BINKY/DEMO01_BINKY.dts`（或项目 overlay）中：

```dts
#include <zephyr/dt-bindings/input/input-event-codes.h>

/ {
	encoder: encoder {
		compatible = "gpio-qdec";
		/* A=P0.10, B=P1.06；公共端 GND；内部上拉 */
		gpios = <&gpio0 10 (GPIO_PULL_UP | GPIO_ACTIVE_HIGH)>,
			<&gpio1 6  (GPIO_PULL_UP | GPIO_ACTIVE_HIGH)>;
		/* 1 卡点 = 4 步，每 4 步上报 1 次 */
		steps-per-period = <4>;
		zephyr,axis = <INPUT_REL_WHEEL>;
		sample-time-us = <1000>;
		idle-timeout-ms = <200>;
	};
};

&uicr {
	nfct-pins-as-gpios;
};
```

> 如果不想改 board 文件，也可用 overlay 实现；具体由确认后决定。

## 5. prj.conf 修改点

当前 `01_code` 未启用 input 子系统，需要新增：

```conf
CONFIG_INPUT=y
```

`CONFIG_INPUT_GPIO_QDEC` 不需要手写：只要 DTS 中存在 `encoder` 节点，驱动会自动启用。

> 参考文档说“prj.conf 零改动”，是因为它的 P1 矩阵已经启用了 input 子系统；本项目 P1 是手动 GPIO 扫描，所以需要补 `CONFIG_INPUT=y`。

## 7. 验证要点（沿用 `编码器.md` §5）

1. **UICR 验证**：烧录后读 `UICR.NFCPINS`（地址 `0x10001200`），确认值为 `0xFFFFFFFE`。
2. **方向标定**：临时开 `CONFIG_INPUT_EVENT_DUMP=y`，观察 `REL_WHEEL` 符号；若右旋为负，交换 DTS 中 A/B 两相顺序。
3. **功能验收**：
   - 顺时针 1 卡点 → `旋钮旋转 顺时针 1 卡点 (本次 +18°, 累计 +18°)`
   - 逆时针 1 卡点 → `旋钮旋转 逆时针 1 卡点 (本次 -18°, 累计 0°)`
   - 转 1 圈 → 累计 ±360°
   - 矩阵按键、旋钮按下功能不回归。
