## 1. 总体结论

两个工程硬件几乎一致，但软件实现方式有较大差异：

- 当前 `01_code` 是“手动矩阵扫描 + gpio-qdec + 手动 ADC + RTC 中断保活”的精简实现；
- 参考 `keyboard` 是“CAF buttons + 硬件 QDEC + voltage-divider 传感器 + PPI 硬件保活”的完整实现。

参考工程更符合 Zephyr/NCS 标准，也是你计划最终达到的目标。

## 2. 功能模块对照表

| 功能模块 | 当前 `01_code` | 参考 `keyboard` | 差异点 |
| --- | --- | --- | --- |
| 矩阵按键 | 手动 GPIO 扫描 `src/app/matrix.c`，自己产生 `button_event` | CAF buttons 模块，`buttons_def.h` 配置行列，自动产生 `button_event` | 当前手动扫描，参考使用 CAF 标准驱动 |
| 按键消费 | `src/app/keymap.c` 只做 RTT 打印 | `keyboard_core.c` 构建 HID 报告 | 当前无 HID，仅日志 |
| 编码器 | `gpio-qdec` + `encoder.c` 桥接，`encoder_event{detents,cw}` | 硬件 QDEC（`qdec0`）+ `encoder.c`，微度累积，`encoder_event{steps}` | 当前用 GPIO 中断解码；参考用硬件 QDEC，不占 GPIOTE |
| IP5306 驱动 | `drivers/ip5306/ip5306.c`，I2C0，RTC 中断保活 | `drivers/ip5306.c`，I2C1，RTC2+PPI+GPIOTE 硬件保活 | I2C 实例不同；保活方案不同；API 不同 |

| 低功耗日志 | `power_state_logger.c` 打印 enter/exit low power | 无专门 logger，但模块有 suspend/resume | 当前有日志模块，参考没有独立日志模块 |
| 按键保活 | `button_wake.c` 发 wake_up/keep_alive | CAF `CONFIG_CAF_BUTTONS_PM_KEEP_ALIVE=y` 自动处理 | 当前自研；参考使用 CAF 标准配置 |

## 3. 矩阵按键差异

### 当前 `01_code`

```text
main 循环 -> matrix_scan() -> button_event
```

- 手动扫描 6 行 × 4 列；
- 行 = 输入 + 下拉；
- 列 = 输出高，逐列扫描；
- 低功耗时改为列输出高 + 行中断唤醒。

### 参考 `keyboard`

```text
CAF buttons -> button_event -> keyboard_core
```

- 使用 `CONFIG_CAF_BUTTONS=y`；
- 行列在 `inc/buttons_def.h` 配置；
- CAF buttons 自带扫描、去抖、低功耗唤醒；
- `keyboard_core.c` 负责按键状态和 HID 报告。

**差异**：参考工程不需要自研矩阵扫描和低功耗行中断唤醒。

---

## 4. 编码器差异

### 当前 `01_code`

```text
gpio-qdec -> INPUT_REL_WHEEL -> encoder.c -> encoder_event
```

- 使用 GPIO 中断解码 A/B；
- 占用 2 个 GPIOTE 通道；
- 事件结构：`detents` + `cw`。

### 参考 `keyboard`

```text
nRF52840 QDEC 外设 -> SENSOR_CHAN_ROTATION -> encoder.c -> encoder_event
```

- 使用硬件 QDEC；
- 不占用 GPIOTE；
- 通过微度累积避免跨 report 丢步；
- 事件结构：`steps`（正=顺时针，负=逆时针，绝对值=卡点数）。

**差异**：参考实现更省 GPIOTE，精度更高。

---

## 5. IP5306 驱动差异

| 对比项 | 当前 `01_code` | 参考 `keyboard` |
| --- | --- | --- |
| 文件 | `drivers/ip5306/ip5306.c` | `drivers/ip5306.c` |
| I2C 实例 | `i2c0` | `i2c1` |
| I2C 地址 | 0x75 | 0x75 |
| 保活方式 | RTC2 中断 + GPIO | RTC2 + PPI + GPIOTE |
| 保活属性 | `keepalive-period-ms` / `keepalive-pulse-ms` | `keep-alive-interval-ms` / `pulse-width-ms` |
| 保活参数 | 8000ms / 500ms | 15000ms / 50ms |
| API | `ip5306_init()` / `ip5306_get_status()` | `ip5306_charge_status()` / `is_charging()` / `is_full()` / `suspend()` / `resume()` |
| 额外功能 | 无 | 设置 BOOST always-on 防止自动关机 |

**差异**：参考驱动使用标准 nrfx_gppi/GPIOTE 资源分配，并支持 suspend/resume。

---

## 6. 电池模块差异

### 当前 `01_code`

```text
手动 ADC -> vbat_mv -> SOC -> battery_event
```

- 直接读取 AIN7；
- 手动控制 BAT_ADC_EN；
- 线性 SOC：3300~4200mV；
- 8 秒周期读取。

### 参考 `keyboard`

```text
voltage-divider sensor -> sensor API -> power_mgr.c -> battery_event
```

- 使用 Zephyr `voltage-divider` 驱动；
- `vbatt` 节点自动管理 BAT_ADC_EN；
- 滑动窗口滤波；
- LUT 计算 SOC：3200~4100mV；
- 1 秒周期，但只在明显变化时发布事件。

**差异**：参考工程更标准，采样更稳，事件更精简。

## 7. 低功耗差异

| 对比项 | 当前 `01_code` | 参考 `keyboard` |
| --- | --- | --- |
| Power Manager | CAF Power Manager | CAF Power Manager |
| 按键唤醒 | 自研矩阵行中断 | CAF buttons 自带唤醒 |
| 电池采样 | 低功耗时手动挂起 | power_mgr 监听 power_down/wake_up 挂起/恢复 |
| 编码器 | 未做 suspend/resume | encoder 监听 power_down/wake_up 挂起/恢复 |
| IP5306 保活 | 不随低功耗停止 | ip5306_suspend/resume 随低功耗停止/恢复 |
| 日志 | `power_state_logger` 打印 enter/exit | 无独立日志模块 |

**差异**：参考工程各模块都按 CAF 标准响应 `power_down_event` / `wake_up_event`。

## 8. 需要重点对齐的点

1. **I2C 实例改为 `i2c1`**
   - 参考工程 IP5306 挂在 `i2c1`，当前挂在 `i2c0`。
   - 这可能是当前 IP5306 读取不稳定的关键差异。

2. **IP5306 驱动对齐参考**
   - 属性名改为 `keep-alive-interval-ms` / `pulse-width-ms`；
   - 增加 BOOST always-on；
   - 增加 suspend/resume；
   - 保活改为 PPI/GPIOTE 硬件方案（参考已实现）。

3. **编码器对齐参考**
   - 使用硬件 QDEC；
   - `encoder_event` 改为 `steps` 结构；
   - 使用微度累积。

4. **电池采样对齐参考**
   - 使用 `voltage-divider` 传感器驱动；
   - `battery_event` 改为 `level + state`；
   - SOC 使用 LUT。

5. **矩阵按键对齐参考**
   - 使用 CAF buttons；
   - 移除自研 `matrix.c` 扫描和行中断唤醒；
   - 按键消费由 `keyboard_core.c` 负责。
