## 1. 需求与目标

实现 18 键蓝牙小键盘的**矩阵按键扫描**功能:

- 6 行 × 4 列矩阵,共 **18 个按键位**(17 颗机械轴 `CPG151101S11-16` + 1 个 EC11 旋钮按键);
- 每键串联 `1N4148W` 二极管(防鬼键/防串扰),二极管**阳极接 ROW 行线、阴极经按键接 COL 列线**;
- 输出 BLE HID 键盘报告(数字小键盘键位:HID Keypad codes);
- 旋钮 EC11 的 **A/B 相位**单独解码(音量/滚动),**按键**并入矩阵 (ROW0, COL3);
- 支持去抖、防鬼键、低功耗(空闲中断唤醒/轮询)。

| **gpio-kbd-matrix 驱动** | `zephyr/drivers/input/input_gpio_kbd_matrix.c` + `input_kbd_matrix.c` | GPIO 键盘矩阵扫描。支持行列扫描、防鬼键检测(`no-ghostkey-check` 可关,本板有二极管)、去抖(`debounce-down/up-ms`)、稳定延时(`settle-time-us`)、实际键掩码(`actual-key-mask`)、空闲模式(`idle-mode` = interrupt/poll/scan) |

### 2.3 CAF(Circuit Architecture Framework)★结论已修正

- 位置:`nrf/subsys/caf/modules/buttons.c` + `Kconfig.buttons`;
- **结论:CAF buttons 模块支持键盘矩阵扫描!** Kconfig 明确说明 "Buttons scanned from key matrix or directly connected GPIO";
- 通过配置文件 `buttons_def.h` 定义 `col[]` / `row[]` 引脚数组(端口+引脚号,非 devicetree 方式);
- 支持:`CONFIG_CAF_BUTTONS_POLARITY_INVERSED`(低有效)、扫描间隔 `CONFIG_CAF_BUTTONS_SCAN_INTERVAL`、去抖、低功耗(行中断唤醒)、按键事件 `button_event{key_id, pressed}`(key_id 由 `KEY_ID(col,row)` 编码);
- 事件消费者:`APP_EVENT_SUBSCRIBE(MODULE, button_event)`(参考 `nrf/samples/caf/src/modules/led_state.c`);
- **局限**:CAF 生态**没有现成的 button_event → BLE HID 键盘上报模块**,需要自写事件消费者将 key_id 映射为 HID 键码后走 `BT_HIDS_DEF` 上报(与方案 A 相同的工作量,但少用一层 input 子系统);
- 参考样例:`nrf/samples/caf`(按钮 → LED)、`nrf/applications/machine_learning`(buttons_def.h 示例)。

### 2.4 两条可行方案对比

| 维度 | 方案 A:Zephyr input 子系统 | 方案 B:CAF buttons |
| --- | --- | --- |
| 矩阵扫描 | ✅ 现成 `gpio-kbd-matrix` | ✅ 现成 `buttons.c` 自带矩阵 |
| 行列→按键码 | ✅ 现成 `input-keymap` | ⚠️ 自写 key_id → HID 映射 |
| HID 键码转换 | ✅ `input_to_hid_code()` | ⚠️ 自写映射表 |
| 事件消费 | ✅ `INPUT_CALLBACK_DEFINE` | ✅ `APP_EVENT_SUBSCRIBE(button_event)` |
| BLE HID 上报 | 自写(参考 nRF 示例) | 自写(同左) |
| 低功耗 | ✅ idle-mode=interrupt | ✅ 行中断唤醒 |
| devicetree 描述 | ✅ 纯 DTS,可维护性好 | ❌ `buttons_def.h` C 宏数组 |
| 依赖 | Zephyr 通用,不绑 Nordic | 依赖 NCS CAF 框架 |

**建议:方案 A(Zephyr input 子系统)**,通用性、可维护性更好;若团队已习惯 CAF 事件架构,方案 B 也可行(工作量相近)。**首期建议选 A,文档后续以 A 为主。**

## 3. 硬件矩阵映射(三方验证:网表 + E73 手册 + nRF52840 手册)

### 3.1 行列信号 → E73 模块引脚 → nRF52840 GPIO(已验证)

| 矩阵信号 | E73 引脚 (U36.x) | 引脚名(E73手册) | 芯片球位 | nRF52840 GPIO | 网表网络 |
| --- | --- | --- | --- | --- | --- |
| ROW0 | U36.28 | P15 | AD10 | **P0.15** | ROW0 |
| ROW1 | U36.22 | P0.07 | M2 | **P0.07** | ROW1 |
| ROW2 | U36.20 | P0.12 | U1 | **P0.12** | ROW2 |
| ROW3 | U36.18 | AI2 | J1 | **P0.04** (AIN2) | ROW3 |
| ROW4 | U36.17 | P1.09 | R1 | **P1.09** | ROW4 |
| ROW5 | U36.16 | P0.08 | N1 | **P0.08** | ROW5 |
| COL0 | U36.15 | AI3 | K2 | **P0.05** (AIN3) | COL0 |
| COL1 | U36.14 | P0.06 | L1 | **P0.06** | COL1 |

| COL3 | U36.10 | AI6 | B9 | **P0.30** (AIN6) | COL3 |

> **关于 ROW2 引脚名的说明(已确认,无冲突)**:
> - 原理图 U36 符号上该引脚标注为 **"P12"**,E73 手册引脚表明确引脚 20 = **"P0.12"**(对应 nRF52840 芯片球位 U1 = P0.12);
> - 原理图存在**简写习惯**(如 ROW0 的 "P15" = P0.15、COL3 的 "AI6" = P0.30),"P12" 即 P0.12 的简写,**两者是同一个引脚**,我方实现按 **P0.12** 使用。
> - P0.04/P0.05/P0.30 为 SAADC 复用引脚,作普通 GPIO 数字输入/输出完全可行(nRF52840 任意引脚均可作 GPIO)。

> 以下仅描述方案要点与配置骨架,**不提交代码**,待确认后实现。

### 4.1 文件规划

| 文件 | 内容 |

| board 或 overlay(`BLE_keyboard.overlay`) | devicetree 节点:`kbd-matrix`(gpio-kbd-matrix)+ `keymap`(input-keymap)+ `qdec`(gpio-qdec) |

### 4.2 devicetree 配置骨架(overlay)

```dts
#include <zephyr/dt-bindings/input/input-event-codes.h>
#include <zephyr/dt-bindings/input/keymap.h>

/ {
    kbd-matrix {
        compatible = "gpio-kbd-matrix";
        /* 行:输入 + 内部上拉 + 低有效(二极管阳极接行线) */
        row-gpios = <&gpio0 15 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,  /* ROW0 P0.15 */
                    <&gpio0 7  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,  /* ROW1 P0.07 */
                    <&gpio0 12 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,  /* ROW2 P0.12 */
                    <&gpio0 4  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,  /* ROW3 P0.04 */
                    <&gpio1 9  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,  /* ROW4 P1.09 */
                    <&gpio0 8  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>;  /* ROW5 P0.08 */
        /* 列:输出拉低扫描,低有效 */
        col-gpios = <&gpio0 5  GPIO_ACTIVE_LOW>,  /* COL0 P0.05 */
                    <&gpio0 6  GPIO_ACTIVE_LOW>,  /* COL1 P0.06 */
                    <&gpio0 26 GPIO_ACTIVE_LOW>,  /* COL2 P0.26 */
                    <&gpio0 30 GPIO_ACTIVE_LOW>;  /* COL3 P0.30 */
        /* 硬件有二极管,关闭鬼键检测 */
        no-ghostkey-check;
        debounce-down-ms = <10>;
        debounce-up-ms = <20>;
        settle-time-us = <50>;
        idle-mode = "interrupt";

        keymap {
            compatible = "input-keymap";
            row-size = <6>;
            col-size = <4>;
            keymap = <
                /* 按 4.3 键帽布局填写,示例: */
                MATRIX_KEY(0, 3, INPUT_KEY_ESC)      /* 旋钮按键 = Esc */
                MATRIX_KEY(1, 0, INPUT_KEY_NUMLOCK)
                ...
            >;
        };
    };

    qdec {
        compatible = "gpio-qdec";
        gpios = <&gpio0 10 (GPIO_PULL_UP | GPIO_ACTIVE_HIGH)>,  /* EC11A P0.10 */
                <&gpio1 6  (GPIO_PULL_UP | GPIO_ACTIVE_HIGH)>;  /* EC11B P1.06 */
        steps-per-period = <4>;
        zephyr,axis = <INPUT_REL_WHEEL>;
        sample-time-us = <2000>;
        idle-timeout-ms = <200>;
    };
};
```

### 4.4 应用层消费(方案要点)

- `INPUT_CALLBACK_DEFINE(DEVICE_DT_GET(DT_NODELABEL(keymap)), cb, NULL)` 注册回调;
- 收到 `INPUT_KEY_*`(type=`INPUT_EV_KEY`,value=1 按下 / 0 释放)后:
  1. `input_to_hid_code(code)` 得到 HID 键码(失败返回 -1 则忽略);
  2. 维护当前按下键集合(≤6 键 + 修饰键),调用 `bt_hids_*` 上报(参考 `peripheral_hids_keyboard`);
  3. 释放事件更新集合并上报。
- 组合/多键:应用层维护按键状态表,与 BLE HID 6KRO 对齐。

### 4.5 若选方案 B(CAF buttons)

- `configuration/<board>/buttons_def.h` 定义:
  ```c
  static const struct gpio_pin col[] = {
      { .port = 0, .pin = 5  }, /* COL0 P0.05 */

      { .port = 0, .pin = 26 }, /* COL2 P0.26 */
      { .port = 0, .pin = 30 }, /* COL3 P0.30 */
  };
  static const struct gpio_pin row[] = {
      { .port = 0, .pin = 15 }, /* ROW0 P0.15 */
      { .port = 0, .pin = 7  }, /* ROW1 P0.07 */
      { .port = 0, .pin = 12 }, /* ROW2 P0.12 */

  ```
- `CONFIG_CAF_BUTTONS=y`、`CONFIG_CAF_BUTTONS_POLARITY_INVERSED=y`;
- 订阅 `button_event`,用 `KEY_COL(key_id)/KEY_ROW(key_id)` 映射 HID 键码后上报。
