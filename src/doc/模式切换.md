## 1. 硬件依据（原理图 / 网表 / 手册交叉验证）

### 1.1 采样通道

| 项 | 值 | 依据 |
| --- | --- | --- |
| ADC 输入 | **AIN5** | 用户要求 |
| 对应 GPIO | **P0.29** | nRF52840 数据手册：AIN5 = P0.29 |
| E73 模块引脚 | **引脚 8** | E73-2G4M08S1C 规格书 第三章引脚表：引脚 8 = "A15"，用途"模拟量输入 5" |
| 原理图网络 | **MODE** | 原理图第 1 页"三模切换"电路，`MODE` 网络连 U36(模块) 引脚 8 |

> 交叉验证：网表 `Netlist_蓝牙小键盘_2026-05-22.tel` 中 `MODE ; C9.1 R5.2 U36.8`，
> 即 MODE 网络 = C9 滤波电容 + R5 分压电阻 + 模块引脚 8（AIN5/P0.29）。一致。

### 1.2 拨档开关分压网络

开关：**U1 = SK-13D07-4**（三档拨档开关），经 R5(1kΩ) 串联到 MODE/AIN5。

| 开关引脚 | 连接 | 说明 |
| --- | --- | --- |
| U1.1 | R18(1kΩ) → GND | 档位 1：拉到地 |
| U1.2 | R5(1kΩ) → MODE (AIN5) | 公共端（经 R5 到 ADC） |
| U1.3 | R16(100kΩ) → 3V3 且 R17(100kΩ) → GND | 档位 2：1.65V 分压点 |
| U1.4 | R19(1kΩ) → 3V3 | 档位 3：拉高到 3.3V |
| U1.5 | R20(1kΩ) → GND | 开关另一组公共端/备用（不参与采样判定） |

> 依据：网表 `'$1N8108' ; R5.1 U1.2`、`'$1N8286' ; R18.1 U1.1`、
> `'$1N8291' ; R16.2 R17.2 U1.3`、`'$1N8311' ; R19.2 U1.4`、`'$1N8424' ; R20.1 U1.5`，
> 3V3 网络含 R16.1/R19.1，GND 网络含 R17.1/R18.2/R20.2。原理图第 1 页"三模切换"框选区域核对一致。

### 1.3 档位电压与阈值

| 档位 | 电路 | 理论电压 | 判定区间（用户要求） |
| --- | --- | --- | --- |
| 1（USB） | R18 1k → GND | ≈ **0 V** | < 825 mV |
| 2（2.4G） | R16/R17 100k/100k 分压 | ≈ **1.65 V** | 825 ~ 2475 mV |
| 3（BLE） | R19 1k → 3V3 | ≈ **3.3 V** | ≥ 2475 mV |

验证：825 mV = 3.3V × 1/4，2475 mV = 3.3V × 3/4，与档位电压 0/1.65/3.3V 完全对应。

## 2. 软件方案

### 2.1 新增事件：`mode_event`

仿照参考工程 `inc/events/mode_event.h`：

```c
enum keyboard_mode {
	KEYBOARD_MODE_USB,   /* 0 */
	KEYBOARD_MODE_2_4G,  /* 1 */
	KEYBOARD_MODE_BLE,   /* 2 */
};

struct mode_event {
	struct app_event_header header;
	enum keyboard_mode mode;
};
APP_EVENT_TYPE_DECLARE(mode_event);
```

事件实现 `src/events/mode_event.c`：log + profile（与其它事件一致）。

### 2.2 新增模块：`mode.c`（模式检测）

对齐参考工程 `keyboard/src/mode.c` 的框架，但阈值改为本次要求：

| 配置 | 值 |
| --- | --- |
| ADC 节点 | `zephyr,user`（DTS 中 `io-channels = <&adc 5>`，即 AIN5） |
| ADC 通道 | channel 5，AIN5，GAIN 1/6，14bit（与参考工程一致） |
| 采样周期 | 100 ms |
| 去抖 | 连续 3 次相同才切换 |
| USB 阈值 | `< 825 mV` |
| 2.4G 阈值 | `825 ~ 2475 mV` |
| BLE 阈值 | `>= 2475 mV` |
| 边界策略 | 落在阈值间隙时保持当前模式不变（与参考一致） |

行为：
- main READY 后启动周期采样；
- **首次采样即发布模式**（上电自动判断拨档位置 → 初始模式）；
- 之后仅在模式变化（去抖通过）时发布 `mode_event`；
- 订阅 `power_down_event` / `wake_up_event`：低功耗时停止采样，唤醒后恢复并重新判定；
- 每次发布同时 `LOG_INF("Mode: USB/2.4G/BLE")`（RTT 可观察）。

### 2.3 DTS 修改（`app.overlay`）

在现有 `&adc` 节点下新增 channel 5（AIN5）：

```dts
&adc {
	channel@5 {
		reg = <5>;
		zephyr,gain = "ADC_GAIN_1_6";
		zephyr,reference = "ADC_REF_INTERNAL";
		zephyr,acquisition-time = <ADC_ACQ_TIME_DEFAULT>;
		zephyr,input-positive = <NRF_SAADC_AIN5>;
		zephyr,resolution = <14>;
	};
};
```

在根节点新增：

```dts
zephyr,user {
	io-channels = <&adc 5>;
};
```

> 与参考工程 mini_keyboard.dts 的 `zephyr,user { io-channels = <&adc 5>; }` 完全一致。

### 2.4 CMakeLists / prj.conf

- CMakeLists.txt：新增 `src/mode.c`、`src/events/mode_event.c`
- prj.conf：无需新增（ADC 已启用，CAF 事件管理器已启用）

## 4. 预留接口（本阶段不实现）

### 4.1 USB HID / BLE HID / 2.4G（预留）

- 传输层模块（`usb_hid_transport` / `ble_hid_service`）不在本期范围；
- 后续接入时以 `mode_event` 为切换依据，各模式只注册/使能对应传输通道。

### 4.2 键盘核心模块（`keyboard_core`）

后续订阅三类事件并构建 HID 上报：
- `mode_event`：决定走哪条 HID 通路（USB / BLE；2.4G 预留）；
- `button_event`：按键状态 → HID 键盘报告；
- `encoder_event`：旋钮 → HID Consumer 报告（音量等）。

### 4.3 发送调度层（缓解旋钮尖峰）

旋钮快速旋转会产生密集的 `encoder_event`（每卡点一个），直接上报易丢数据。后续新增**发送调度层**：
- 事件入队 + 定时批量发送（如 1ms 窗口聚合多个 consumer 事件）；
- 或高水位合并：一次 report 内合并多个卡点步数；
- 传输层只消费调度层产出的报告，不直接订阅 `encoder_event`。

## 6. 风险与备注

- **档位电压余量**：2.4G 档 1.65V 处于 825~2475mV 区间中部，余量充足；USB 0V、BLE 3.3V 远离边界，抗干扰好。
- **去抖**：3 次 × 100ms = 300ms，拨档抖动可被滤除；如需更快响应可降至 2 次。
- **参考工程阈值不同**：参考 keyboard `mode.c` 用的是 500/1000~2300/2800mV（旧分压网络），本方案以**当前硬件网表/原理图**为准，采用 825/2475mV。
- **U1.5/R20** 为开关第二组触点，软件不依赖，仅记录。
- **低功耗时拨档不唤醒（方案 A，已确认）**：
  - 拨档开关只接 ADC（AIN5/P0.29），无独立 GPIO 唤醒线；键盘 suspended 时 `mode.c` 停止采样，拨档不产生中断、不唤醒。
  - 不能简单用 P0.29 做 GPIO 边沿唤醒：nRF52 输入阈值 Vih≈2.31V / Vil≈0.99V，2.4G 档 1.65V 落在不确定区，边沿检测不可靠。
  - 模式更新时机：唤醒后（按键矩阵行中断 / USB VBUS / 其它唤醒源）`mode.c` 重新采样并发布 `mode_event`。
  - 与参考工程行为一致；后续 USB 栈接入后，USB 插入的 VBUS 检测天然覆盖"睡眠时切到 USB 档"场景。

## 7. 验收标准（用户要求）

| # | 要求 | 实现要点 | 验证方式 |
| --- | --- | --- | --- |
| 1 | **三个档位识别准确** | mode.c 按 825/2475mV 阈值判档；`zephyr,user`=AIN5 | RTT 打印 `Mode: USB/2.4G/BLE` 与拨档位置一致；反复拨动无错判 |
| 2 | **切换不会反复抖动** | 连续 3 次采样一致才发布 mode_event；首次采样即定初始模式 | 快速拨动/停在边界，RTT 只打印一次模式变化，无来回横跳 |
| 3 | **屏幕模式显示正确** | 预留 display 模块订阅 mode_event，按模式切换屏幕指示（当前工程无屏幕硬件，先定义接口） | 屏幕显示当前模式文案/图标（后续接入屏幕后验证） |
| 4 | **USB/BLE 栈按模式启停** | usb_hid_transport 订阅 mode_event：USB 档 `usbd_enable`，否则 `usbd_disable`；ble_hid_service 订阅 mode_event：BLE 档 `ble_start`，否则 `ble_stop` | USB 档枚举出 HID 设备；BLE 档可连接；其它档对应栈关闭 |

### 7.1 各模块对 mode_event 的响应矩阵

| 模块 | USB 档 | 2.4G 档 | BLE 档 |
| --- | --- | --- | --- |
| usb_hid_transport | `usbd_enable` | `usbd_disable` | `usbd_disable` |
| ble_hid_service | `ble_stop` | `ble_stop` | `ble_start` |
| display（预留） | 显示 USB | 显示 2.4G | 显示 BLE |
| 2.4G 传输（预留） | 停 | **启（预留）** | 停 |

> 参考依据：参考工程 `usb_hid_transport.c` 中 `if (evt->mode == KEYBOARD_MODE_USB) usbd_enable(&usbd_ctx); else usbd_disable(&usbd_ctx);`；
> `ble_hid_service.c` 中 `if (mode == KEYBOARD_MODE_BLE) ble_start(); else ble_stop();`。
