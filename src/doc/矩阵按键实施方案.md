## 2. 本期实现架构(按键模块)

### 2.1 事件流(本期)

```
CAF buttons (矩阵扫描, buttons_def.h: 4列 × 6行)
   └─→ button_event {key_id, pressed}        ← 按下/释放,key_id = KEY_ID(col, row)
          │  [日志] 打印 [row,col] 键名 按下/释放 (中文键名)
          ▼
   click_detector ──→ click_event (短按/长按)
          │   旋钮按键(0,3) 短按 → 音量开关(MUTE 切换)
          ▼
   [预留] hid_state → hid_provider_keyboard → HID 报告 (本期不接 BLE/USB,仅保留链路)
          ▼
   [预留] hids (BLE) / usb_state (USB) —— 后续阶段接入

EC11 旋转 (Zephyr gpio-qdec) ──→ INPUT_REL_WHEEL
   └─→ [自研] wheel 桥接 ──→ CAF wheel_event
          └─→ 音量调节:VOLUME_UP(0x00E9) / VOLUME_DOWN(0x00EA)
              每格一次,无长按连发
```

### 2.2 本期验证输出(串口日志)

- **矩阵按键**:按下打印 `[0,3] 旋钮按键 按下`,释放打印 `[0,3] 旋钮按键 释放`;其余键同理(中文键名表见 §4.3);
- **旋钮音量**:旋转一格打印 `音量 +1` / `音量 -1`(或对应 HID usage);
- **旋钮按下**:打印 `[0,3] 旋钮按键 短按 → 音量开关(静音)`;
- 同时支持打印原始 `key_id` / `(row,col)` 便于调试。

## 3. GPIO 配置(按用户修正)

### 3.1 极性说明(重要修正)

| 信号 | 方向 | 配置 | 说明 |
| --- | --- | --- | --- |
| **行 ROW0~ROW5** | 输入(读取) | `GPIO_PULL_DOWN \| GPIO_ACTIVE_HIGH` | 内部下拉,按键按下时行被拉**高**,高有效 |
| **列 COL0~COL3** | 输出(驱动) | `GPIO_ACTIVE_HIGH` | 扫描时逐列输出**高**,高有效 |

> 与上一版(行上拉低有效/列低有效)**相反**,已按用户确认修正。
> 对应二极管方向:电流从**列(高) → 按键 → 二极管 → 行(被拉高)**,行内部下拉保证未按下时读低。

### 3.2 devicetree 配置(参考,若用 Zephyr gpio-kbd-matrix)

```dts
kbd-matrix {
    compatible = "gpio-kbd-matrix";
    /* 行:输入 + 内部下拉 + 高有效(按下为高) */
    row-gpios = <&gpio0 15 (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>,  /* ROW0 P0.15 */
                <&gpio0 7  (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>,  /* ROW1 P0.07 */
                <&gpio0 12 (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>,  /* ROW2 P0.12 */
                <&gpio0 4  (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>,  /* ROW3 P0.04 */
                <&gpio1 9  (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>,  /* ROW4 P1.09 */
                <&gpio0 8  (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>;  /* ROW5 P0.08 */
    /* 列:输出拉高扫描,高有效 */
    col-gpios = <&gpio0 5  GPIO_ACTIVE_HIGH>,  /* COL0 P0.05 */
                <&gpio0 6  GPIO_ACTIVE_HIGH>,  /* COL1 P0.06 */
                <&gpio0 26 GPIO_ACTIVE_HIGH>,  /* COL2 P0.26 */
                <&gpio0 30 GPIO_ACTIVE_HIGH>;  /* COL3 P0.30 */
    no-ghostkey-check;   /* 硬件有二极管,关闭软件防鬼键 */
    debounce-down-ms = <10>;
    debounce-up-ms = <20>;
};
```

> 用户示例 `<&gpio0 7 (GPIO_PULL_DOWN | GPIO_ACTIVE_HIGH)>`、`<&gpio0 6 GPIO_ACTIVE_HIGH>` 即此格式(ROW1/COL1 位)。

### 3.3 CAF buttons_def.h 配置(本项目实际采用)

CAF buttons 用 C 数组配置(非 devicetree),等价实现:

```c
#include <caf/gpio_pins.h>
const struct {} buttons_def_include_once;

/* 列:输出驱动,高有效 */
static const struct gpio_pin col[] = {
    { .port = 0, .pin = 5  },  /* COL0 P0.05 */
    { .port = 0, .pin = 6  },  /* COL1 P0.06 */
    { .port = 0, .pin = 26 },  /* COL2 P0.26 */
    { .port = 0, .pin = 30 },  /* COL3 P0.30 */
};

/* 行:输入读取,下拉,高有效(按下为高) */
static const struct gpio_pin row[] = {
    { .port = 0, .pin = 15 },  /* ROW0 P0.15 */
    { .port = 0, .pin = 7  },  /* ROW1 P0.07 */
    { .port = 0, .pin = 12 },  /* ROW2 P0.12 */
    { .port = 0, .pin = 4  },  /* ROW3 P0.04 */
    { .port = 1, .pin = 9  },  /* ROW4 P1.09 */
    { .port = 0, .pin = 8  },  /* ROW5 P0.08 */
};
```

`prj.conf` 关键项:

```
CONFIG_CAF_BUTTONS=y
CONFIG_CAF_BUTTONS_SCAN_INTERVAL=6
CONFIG_CAF_BUTTONS_DEBOUNCE_INTERVAL=6
# 列输出高、行下拉读高 → 不反转极性
# CONFIG_CAF_BUTTONS_POLARITY_INVERSED 保持 n(默认)
```

> **去抖参数(用户确认)**:按键去抖 **按下 10ms / 释放 10ms**。CAF buttons 的去抖由扫描/去抖间隔实现(`SCAN_INTERVAL` + `DEBOUNCE_INTERVAL`),实现时以实际效果为准调整为约 10ms/10ms 等效值;若使用 Zephyr input 方案则对应 `debounce-down-ms = <10>`、`debounce-up-ms = <10>`。
> CAF buttons 默认行为:列配置 `GPIO_OUTPUT` 输出,行配置 `GPIO_INPUT + GPIO_PULL_DOWN`,读原始值,高=按下。与 §3.1 极性一致。

## 5. 旋钮(EC11)本期实现

| 项 | 值 |
| --- | --- |
| A 相位 | P0.10 (U36.43/NF2) |
| B 相位 | P1.06 (U36.42) |
| 解码 | Zephyr `gpio-qdec`(steps-per-period=4, zephyr,axis=INPUT_REL_WHEEL) |
| 事件桥接 | gpio-qdec REL_WHEEL → 自研 wheel 桥接 → CAF wheel_event |
| **音量调节(旋转)** | 每格一次:VOLUME_UP(0x00E9) / VOLUME_DOWN(0x00EA);**无长按连发** |
| **音量开关(按下)** | 旋钮**按下**(click_detector 短按)→ **静音开/关**(MUTE,Consumer Control 0x00E2 切换) |
| **Esc(预留)** | 已确认可映射 Esc,但本期不做,预留接口(后续接入 hid_keymap) |

## 7. 工程组织建议

用户疑问"基于 nRF Desktop 裁剪,还是拷贝模块到本项目"——结合未来需求(三模切换 + 显示屏 + 灯效),建议:

**以 nRF Desktop 工程为基底,裁剪为本项目专用工程(用户已确认)**

理由:
1. nRF Desktop 已内置全部所需模块(buttons/hid/selector/led/dfu/battery/低功耗),未来加三模、显示、灯效时**直接启用对应模块**,无需跨工程拷贝;
2. 裁剪方式:复制 nrf_desktop,删掉不需要的模块(fast_pair/dfu/motion 等),保留核心;或新建工程后从 nrf_desktop 选择性包含(src/CMakeLists.txt 控制);
3. 本项目 board 定义(`BLE_keyS/BLE_keyboard`)作为自定义 board 加入,覆盖现有 nrf52kbd 配置;
4. 未来演进路径清晰:本期只开按键+旋钮;M 阶段逐步开 selector(三模)、LVGL(显示)、hids(BLE)、RGB(灯效)。

> 备选(不采用):拷贝所需模块到本项目现有 Zephyr 工程——适合最小验证,但未来模块增长后管理成本高。
