# 蓝牙小键盘 — 编码器（旋钮）实现方案与验证方案

> 版本 v1.0（2026-08-31，待用户确认）
> 前置阶段：矩阵按键（P1）已完成并构建通过，本方案在其基础上叠加编码器功能。

## 0. 结论摘要（TL;DR）

1. **Zephyr 有现成驱动**：`input-gpio-qdec`（compatible `gpio-qdec`），正交解码 + 消抖 + 空闲中断唤醒，全部内置。**采用**，不重复造轮子。
2. **CAF 无现成编码器模块/事件**（已核实 nrf/subsys/caf 全量模块与事件），因此按 P1 矩阵的既定模式：自研桥接模块 `encoder.c`（input 事件 → 自定义 `encoder_event`）→ keymap 消费并 RTT 打印。
3. **NFC 禁用**：本 SDK（Zephyr 4.2.99）已移除 `CONFIG_NFCT_PINS_AS_GPIOS`，新机制是板级 DTS 写 UICR：`&uicr { nfct-pins-as-gpios; };`（Zephyr ≥3.5 官方迁移说明，nrf52840dongle 等现成板同款写法）。
4. **20 卡点 = 80 步**：EC11 每卡点对应 1 个完整正交周期（4 步），驱动属性 `steps-per-period = <4>` 后**每转过 1 个卡点恰好上报 1 次事件**，事件值 ±1 即"卡点数"，天然满足需求。
5. **打印目标**：`旋钮旋转 顺时针 1 卡点 (角度 +18°)`（方向 + 卡点数，角度由卡点数 ×18° 换算，格式细节见 §7 待确认）。

## 1. 硬件基础（网表核实）

依据：`src/source/Netlist_蓝牙小键盘_2026-05-22.tel`（权威）与 `SCH_蓝牙小键盘_2026-03-28.pdf`（图形佐证）。

### 1.1 编码器引脚与电路（网表行号证据）

| 项 | 值 | 网表证据 |
|----|----|---------|
| 型号 | EC11E15244G1（带按下键 SW3） | L60 |
| A 相 | EC11A = U36.43 = **P0.10**（NFC2） | L159 `EC11A ; C40.1 SW3.A U36.43` |
| B 相 | EC11B = U36.42 = **P1.06** | L160 `EC11B ; C31.2 SW3.B U36.42` |
| 公共端 C | **GND** | L166（GND 网络含 SW3.C） |
| 按下键 | SW3.D=列 C3、SW3.E=行 R0 → 矩阵 (0,3)，**P1 已实现** | L105/L156 |
| A 相滤波 | C40 = 100nF 到地 | L159 + L165（C40.2 ∈ GND） |
| B 相滤波 | C31 = 100nF 到地 | L160 + L164（C31.1 ∈ GND） |
| 外部上拉 | **无**（网络成员仅电容/开关/模组脚） | 同上 |

结论：
- 公共端接 GND → A/B 悬空位靠 **GPIO 内部上拉**为高，导通位被拉到低。DTS 必须写 `GPIO_PULL_UP`（nRF52840 内部上拉典型 13kΩ）。
- 内部上拉 13kΩ × 100nF ≈ **RC 1.3ms**，影响采样参数选择与极速旋转上限（见 §4.1/§6）。
- 按下键已在矩阵阶段完成，本阶段**不重复实现**。

### 1.2 编码器参数与换算（用户提供 + 型号佐证）

| 参数 | 值 | 说明 |
|------|----|------|
| 卡点/圈 | 20 | 物理卡点 |
| 步/圈 | 80（4 倍频解码） | 每卡点 = 1 完整正交周期 = 4 个边沿 |
| 角度/步 | 360° / 80 = **4.5°** | |
| 角度/卡点 | 360° / 20 = **18°** | 打印中的角度 = 卡点数 × 18° |

驱动侧实现方式：`steps-per-period = <4>` → 驱动每累计 4 步上报 1 次 `INPUT_REL_WHEEL`（值 ±1/卡点），正好把"步"折算成"卡点"再上报。

### 1.3 NFC 引脚（P0.09/P0.10）现状

| 引脚 | 网络 | 释放为 GPIO 后的影响 |
|------|------|--------------------|
| P0.10（NFC2） | EC11A | 本阶段目标：编码器 A 相输入 |
| P0.09（NFC1） | BAT_ADC_EN（Q1 门极，经 R9） | Q1 门极有 **R10 下拉到地**（网表 L165：R10.2 ∈ GND），P0.09 浮空时 Q1 保持关断，**无副作用**。本阶段不配置 P0.09 |

## 2. 调研结论（源码实录）

### 2.1 Zephyr 现成驱动：input-gpio-qdec（选型依据）

文件：`F:/ncs/v3.2.3/zephyr/drivers/input/input_gpio_qdec.c`（437 行）+ 绑定 `zephyr/dts/bindings/input/gpio-qdec.yaml`。

机制（读源码逐行确认）：
- **正交解码**：8 种有效跳变全查表（L53-62），无效跳变只 LOG_WRN 不计数——机械抖动天然免疫；
- **空闲中断唤醒**：空闲时 A/B 配 `GPIO_INT_EDGE_BOTH` 中断（gpio_nrfx 实现为 GPIOTE TOGGLE 模式，**每脚占 1 个 GPIOTE 通道**，gpio_nrfx.c L395），任意跳变即转轮询；
- **轮询跟踪**：以 `sample-time-us` 周期采样 A/B（计时器上下文），`idle-timeout-ms` 内无跳变回空闲（L209/L231）；
- **事件协议**：累计值 `|acc| ≥ steps-per-period` 时经工作队列投递 `input_report_rel(dev, axis, acc/steps_per_period, sync=true)`（L205-228）——事件值 = 折算后的**卡点数**（正常速度 ±1，快速旋转一次可 ±2/+3），余数保留不丢步；
- **无官方示例/测试**（本 SDK 的 samples/tests 中无 gpio-qdec 用例），桥接层需自研（见 §4.3）。

DT 必填属性：`gpios`（A、B 两相，顺序敏感）、`steps-per-period`、`zephyr,axis`、`sample-time-us`、`idle-timeout-ms`。可选：`led-gpios`/`led-pre-us`/`idle-poll-time-us`（本硬件无 LED，不用）。

Kconfig：`CONFIG_INPUT_GPIO_QDEC`，`default y` + `depends on DT_HAS_GPIO_QDEC_ENABLED` → **DTS 有节点即自动启用**，prj.conf 无需手写。

### 2.2 CAF 侧现状（无现成 → 自研桥接）

- `nrf/subsys/caf/modules/` 全量核对：buttons、leds、click_detector、power_manager、sensor_manager、settings_loader……**无 encoder 模块**；
- `nrf/include/caf/events/` 全量核对：button_event、click_event、led_event、sensor_event……**无 wheel/encoder 事件**；
- nrf_desktop 的 wheel_event/wheel 模块是应用级代码，且基于 QDEC **外设**（sensor API），不适用于本项目 GPIO 接线的 EC11，不采用；
- 结论：与 P1 矩阵同构——**驱动用 Zephyr 现成的，桥接层自研**。自定义 `encoder_event` 完全照抄 `button_event` 的官方模板（`nrf/include/caf/events/button_event.h` + `nrf/subsys/caf/events/button_event.c`：`APP_EVENT_TYPE_DECLARE`/`APP_EVENT_INFO_DEFINE`/`APP_EVENT_TYPE_DEFINE` 三件套）。

### 2.3 NFC 禁用的新机制（本 SDK 实测核实）

- 旧符号 `CONFIG_NFCT_PINS_AS_GPIOS` 在本 SDK 全树**已不存在**（仅 TF-M 侧有 `TFM_NFCT_PINS_AS_GPIOS`，与本项目无关）；
- Zephyr 3.5 官方迁移说明（`doc/releases/migration-guide-3.5.rst` L377-385）：改用 **UICR 设备树属性**：

```dts
&uicr {
	nfct-pins-as-gpios;
};
```

- `nrf52840.dtsi` 的 uicr 节点已 `status="okay"`（L55-59），绑定 `dts/bindings/arm/nordic,nrf-uicr.yaml` L11 定义该属性；现成板卡 `nrf52840dongle_nrf52840_common.dtsi` L114 等均在用；
- 属性由构建系统编入 UICR 区数据，**烧录时写入 UICR.NFCPINS**；是否生效可在烧录后读回验证（见 §5.2）。

## 3. 总体架构

```
EC11（A=P0.10, B=P1.06, 公共端 GND）
   │  A/B 正交信号（内部上拉 + 板上 100nF 滤波）
   ▼
gpio-qdec 驱动（Zephyr input 子系统，现成）
   │  INPUT_REL_WHEEL value=±卡点数（sync 收尾）
   ▼
encoder.c 桥接模块（自研，仿 matrix.c）
   │  自定义 encoder_event { detents, cw }
   ▼
keymap.c 扩展（订阅 encoder_event）
   │  RTT: "旋钮旋转 顺时针 1 卡点 (角度 +18°)"
```

与 P1 矩阵架构完全同构：**驱动层用现成 input 驱动，桥接层自研转 CAF 事件，输出层统一在 keymap 打印**。P1 的 matrix.c/keymap.c 不改动逻辑，keymap.c 只新增 encoder_event 订阅分支。

## 4. 实现方案

### 4.1 板级 DTS（boards/atguigu/mini_keyboard/mini_keyboard.dts）

```dts
/* 文件头部追加（INPUT_REL_WHEEL 宏定义来源） */
#include <zephyr/dt-bindings/input/input-event-codes.h>

/* / { } 内与 kbd_matrix 并列 */
	/* ===== 编码器 EC11（20 卡点/圈 = 80 步，1 卡点 = 4 步） ===== */
	encoder: encoder {
		compatible = "gpio-qdec";
		/* A、B 两相（公共端接地，内部上拉；顺序决定方向语义，勿改） */
		gpios = <&gpio0 10 (GPIO_PULL_UP | GPIO_ACTIVE_HIGH)>,  /* A 相 EC11A = P0.10 */
			<&gpio1 6  (GPIO_PULL_UP | GPIO_ACTIVE_HIGH)>;  /* B 相 EC11B = P1.06 */
		/* 每累计 4 步上报 1 次 → 事件值即卡点数 */
		steps-per-period = <4>;
		zephyr,axis = <INPUT_REL_WHEEL>;
		/* 板上 100nF 滤波 + 13kΩ 内部上拉 ≈ RC 1.3ms，采样取 1ms（初值，实测微调） */
		sample-time-us = <1000>;
		idle-timeout-ms = <200>;
	};

/* 文件末尾追加（NFC 引脚释放为 GPIO，Zephyr ≥3.5 新机制） */
&uicr {
	nfct-pins-as-gpios;
};
```

要点：
- 不设 `idle-poll-time-us` → 用中断唤醒（省电，电池设备）；代价是 A/B 各占 1 个 GPIOTE 通道（§6 R1）。
- 方向语义：驱动"正方向"= A 相先于 B 相变化。首版标定后若"顺时针/逆时针"与实际旋向相反，**只交换 gpios 两相顺序**（不动代码）。
- P0.09（BAT_ADC_EN）本阶段不配置（默认 GPIO 输入，Q1 有 R10 下拉保护，§1.3）。

### 4.2 prj.conf 变化

### 4.3 自定义事件 src/app/encoder_event.h/.c（照抄 button_event 官方模板）

```c
/* encoder_event.h 要点 */
#include <app_event_manager.h>
#include <app_event_manager_profiler_tracer.h>

/** 旋钮旋转事件：每转过 N 卡点由 encoder.c 桥接投递一次 */
struct encoder_event {
	struct app_event_header header;
	uint8_t detents;   /**< 本次旋转卡点数（≥1） */
	bool cw;           /**< 方向：true=顺时针（以 §5.2 标定为准） */
};

APP_EVENT_TYPE_DECLARE(encoder_event);

/* encoder_event.c 要点（与 button_event.c 同构） */
static void log_encoder_event(const struct app_event_header *aeh)
{
	const struct encoder_event *event = cast_encoder_event(aeh);
	APP_EVENT_MANAGER_LOG(aeh, "detents=%u %s", event->detents,
			      event->cw ? "cw" : "ccw");
}
APP_EVENT_INFO_DEFINE(encoder_event, ...);
APP_EVENT_TYPE_DEFINE(encoder_event, log_encoder_event, &encoder_event_info,
		      APP_EVENT_FLAGS_CREATE(APP_EVENT_TYPE_FLAGS_INIT_LOG_ENABLE));
```

### 4.4 桥接模块 src/app/encoder.c（仿 matrix.c）

职责：订阅 encoder 设备的 input 事件 → 投递 `encoder_event`；同时按 demo02 惯例注册为 CAF 模块（等 main READY 后置 READY）。

```c
#define ENCODER_DEV_NODE DT_NODELABEL(encoder)

static void encoder_input_cb(struct input_event *evt, void *user_data)
{
	if (evt->code != INPUT_REL_WHEEL || !evt->sync) {
		return;		/* 只取 REL_WHEEL 且 sync 收尾的那一次 */
	}
	if (evt->value == 0) {
		return;
	}

	struct encoder_event *event = new_encoder_event();

	event->detents = abs(evt->value);	/* 驱动已按 4 步/卡点折算 */
	event->cw = (evt->value > 0);		/* 符号=方向，标定见 §5.2 */
	APP_EVENT_SUBMIT(event);
}
INPUT_CALLBACK_DEFINE(DEVICE_DT_GET(ENCODER_DEV_NODE), encoder_input_cb, NULL);
/* + demo02 模式 module_state_event 生命周期（等 main READY 后置 READY） */
```

要点：回调运行在驱动工作队列上下文（input_report_rel 的 work 上下文），CAF 事件机制线程安全，直接投递；与 matrix.c 同模式。

### 4.5 keymap.c 扩展：订阅 encoder_event 并打印

```c
static int32_t knob_angle_deg;	/* 累计角度（度），重启清零 */

if (is_encoder_event(aeh)) {
	struct encoder_event *event = cast_encoder_event(aeh);
	int32_t delta = (int32_t)event->detents * 18 * (event->cw ? 1 : -1);

	knob_angle_deg += delta;
	/* 例: "旋钮旋转 顺时针 1 卡点 (本次 +18°, 累计 +18°)" */
	LOG_INF("旋钮旋转 %s %u 卡点 (本次 %s%d°, 累计 %s%d°)",
		event->cw ? "顺时针" : "逆时针", event->detents,
		delta >= 0 ? "+" : "", delta,
		knob_angle_deg >= 0 ? "+" : "", knob_angle_deg);
	return false;	/* 传播不消费 */
}
/* APP_EVENT_SUBSCRIBE(keymap, encoder_event); */
```

换算公式：**角度 = 卡点数 × 18°**（80 步/圈 = 20 卡点/圈，§1.2）。打印格式细节待确认（§7-1）。

## 5. 验证方案

### 5.1 构建与烧录

```bash
west build -b mini_keyboard --build-dir build -- -DSNIPPET=rtt-console \
    -DBOARD_ROOT=<项目根目录>
west flash --build-dir build
```

- 构建环境与 P1 相同（见 矩阵按键.md §5.1；ZEPHYR_BASE/BOARD_ROOT/工具链 env）。
- **注意 UICR**：`nfct-pins-as-gpios` 会编入固件的 UICR 数据段，`west flash` 自动写入（UICR 非易失，写一次永久生效；开发期全片擦除烧录每次自动重写，无需手动操作）。默认 runner 以 board.cmake 实际选择为准（jlink/nrfjprog 均支持）。

### 5.2 硬件标定（Step 3 烧录后即做）

1. **UICR 读回验证**：`nrfjprog --memrd 0x10001200 --n 4`（UICR.NFCPINS 偏移 0x200），确认写入的 NFCPINS 值 = `0xFFFFFFFE`（bit0=0 → NFC 引脚释放为 GPIO）；若无 nrfjprog，用 J-Link 读同地址。
2. **原始事件标定**（临时配置，不进正式固件）：追加 `CONFIG_INPUT_EVENT_DUMP=y` 重编烧录 → RTT 观察：
   - 慢转 1 个卡点 → 应恰好出现 1 组 `REL_WHEEL value=±1 sync`（若 1 卡点出 4 个事件说明 steps-per-period 写错；若无事件查上拉/引脚）；
   - **方向标定**：右旋（顺时针）→ 记录 value 符号。若右旋 value=-1，交换 DTS 中两相顺序重编（一次定死，之后不动代码）。
3. 恢复正式配置（去掉 INPUT_EVENT_DUMP）重编烧录。

### 5.3 逐项功能测试（核心验收）

| 编号 | 操作 | 预期 RTT |
|------|------|---------|
| E01 | 顺时针慢转 1 卡点 | `旋钮旋转 顺时针 1 卡点 (本次 +18°, 累计 +18°)` |
| E02 | 逆时针慢转 1 卡点 | `旋钮旋转 逆时针 1 卡点 (本次 -18°, 累计 0°)` |
| E03 | 顺时针连续转 5 卡点 | 5 次 ×1 卡点（或 1 次 ×5，快速时驱动可合并上报，累计 +90°） |
| E04 | 顺/逆交替 3 轮 | 方向逐次正确切换，累计角度正确（手工核算） |
| E05 | 快速转 10 卡点（约 0.5s 内） | 卡点总数 = 10±0（允许一次事件多卡点），累计 ±180° |
| E06 | 旋转 + 按下旋钮键同时操作 | 打印互不干扰：按下/释放（P1 格式）与旋转打印交替出现，无丢事件 |
| E07 | 旋转 + 按 NumLock 等矩阵键 | 矩阵 18 键行为不回归（与 P1 §5.3 T01-T18 抽测） |
| E08 | 静止 5 秒 | 无任何打印（idle 正常，无抖动脉冲） |

### 5.4 消抖与丢步测试（Step 4 依据）

- 正向/反向各快速旋转 100 卡点（20 卡点 ×5 圈），核对累计角度 = ±1800°；允许误差 ≤1 卡点（1%），超差则调 `sample-time-us`（初值 1000us，可试 500us）重测；
- 半卡点位置松手：不产生事件（定位款 EC11 会自行弹回卡点，允许 ±1 卡点回弹事件）。

### 5.5 验收标准（本阶段）

1. RTT 能打印出旋转**方向、卡点数、角度**（角度=卡点数×18°，累计正确）；
2. 80 步/圈 与 20 卡点/圈 的换算在 RTT 上可复核（转 1 圈 = 累计 ±360°）；
3. 矩阵按键 18 键功能无回归；
4. 旋钮按下键功能无回归（P1 已实现，本阶段不重复实现）。

## 6. 风险与注意事项

- **R1 GPIOTE 通道恰好用满（8/8）**：矩阵 6 行空闲中断 + 编码器 A/B 双沿中断（每脚 1 通道，gpio_nrfx TOGGLE 实现）共 8 个 = nRF52840 全部通道。若后续阶段再加中断引脚或运行时报 GPIOTE 分配失败：方案 a) 编码器 DTS 增加 `idle-poll-time-us`（空闲轮询，不占中断，代价是空闲耗电）；方案 b) 矩阵 `idle-mode = "poll"`。本阶段先按默认实现，出错即启用 a。
- **R2 RC 滤波限速**：100nF + 13kΩ 内部上拉 ≈ RC 1.3ms。人手旋转（每卡点 ≥20ms）无影响；若出现极速丢步属电气层限制，可更换更小滤波电容（硬件改动，不属本阶段）。
- **R3 UICR 写入依赖烧录器**：`nfct-pins-as-gpios` 必须真正写入 UICR 才生效；§5.2 步骤 1 读回验证兜底。若只改代码不重新烧 UICR，P0.10 会被 NFC 占用导致编码器无声。UICR 为非易失存储，写一次永久生效；但 OTA（MCUboot DFU）镜像不含 UICR 段，**量产时首次完整烧录必须带 UICR 数据（一次性），后续 OTA 无需重复**。
- **R4 P0.09 连带释放**：UICR 一次性释放 NFC1+NFC2 两脚。P0.09（BAT_ADC_EN）浮空但 Q1 门极有 R10 下拉（网表 L165），电量分压网络保持关断，无副作用。**后续电池采样阶段需记得主动驱动 BAT_ADC_EN**。
- **R5 方向语义依赖接线**：A/B 相序由 §5.2 标定一次定死；换硬件批次/改版需重标。
- **R6 快速旋转事件合并**：驱动按 `acc/steps_per_period` 一次上报多卡点（如 value=±3），打印层已按"detents 卡点"处理，属预期行为。

## 7. 已确认决策（2026-08-31，确认后开始编码）

1. **RTT 打印格式**：`旋钮旋转 顺时针 1 卡点 (本次 +18°, 累计 +18°)`（方向 + 卡点数 + 本次/累计角度，± 符号）。
2. **累计角度口径**：模块内 int32_t 累计、重启清零，只作 RTT 显示、不持久化。
3. **事件架构**：自定义 `encoder_event`（照抄 button_event 官方模板），本阶段打印在 keymap.c（P2/HID 阶段可直接复用该事件做音量/层切换）。
4. **消抖/采样初值**：sample-time-us=1000、idle-timeout-ms=200，先按此值实现、§5.4 实测定稿。
5. **NFC UICR 写入机制**（已澄清）：UICR 是非易失存储，写一次永久生效；"每次烧录写入"指开发期全片擦除烧录时构建产物自动携带 UICR 段重写，无需手动操作。量产/OTA：OTA 镜像不含 UICR，产线首次完整烧录带 UICR（一次性），后续 OTA 无需重复。
