# 电源管理模块实现说明（IP5306 + 电池状态 + 低功耗唤醒）

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |

| 适用工程 | `01_code` |
| 状态 | 已实现，编译验证通过 |

---

## 1. 概述

本项目电源管理模块主要完成以下工作：

1. 为 IP5306 PMIC 编写 out-of-tree Zephyr 驱动。
2. 通过 I2C 读取 IP5306 的 charging / full 状态。
3. 通过 RTC2 中断 + GPIO 控制产生 IP5306 keepalive 脉冲，避免占用 GPIOTE。
4. 通过 ADC 采样电池电压，并计算 SOC。
5. 通过 `battery_module` 周期性读取并发布电池状态事件。
6. 配合 CAF Power Manager 实现低功耗 suspended 状态和按键唤醒。

整体遵循一个原则：

> 驱动层用 Zephyr 标准机制（devicetree + driver model），业务层用 CAF 事件总线（app_event_manager），硬件定时尽量用 Nordic 外设，不依赖线程定时器。

---

## 2. 整体架构

```text
IP5306 PMIC
   │
   ├─ I2C0（SDA=P1.00, SCL=P0.24, addr=0x75）
   │     └─ ip5306.c 驱动
   │           ├─ ip5306_get_status()
   │           │     ├─ 读 0x70 bit3 -> charging
   │           │     └─ 读 0x71 bit3 -> full
   │           └─ 硬件 keepalive
   │                 ├─ RTC2 计时
   │                 └─ RTC 中断控制 P0.22
   │
   ├─ BAT_ADC（P0.31 / AIN7）
   │     └─ ADC 采样 -> 电池电压 -> SOC
   │
   └─ BAT_ADC_EN（P0.09）
         └─ 采样时使能分压网络，省电

battery_module.c
   ├─ 初始化 IP5306
   ├─ 周期读取 charging/full
   ├─ 周期读取电压/SOC
   └─ 发布 battery_event 到 app_event_manager

CAF Power Manager
   ├─ 空闲超时进入 suspended
   ├─ 按键按下发送 wake_up_event
   └─ 退出低功耗
```

## 3. 硬件依据

### 3.1 IP5306 接口

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| I2C SDA | P1.00 | I2C0 数据 |
| I2C SCL | P0.24 | I2C0 时钟 |
| IP5306 地址 | 0x75 | 7-bit I2C 地址 |
| WAKEUP/Keepalive | P0.22 | Active low，低电平有效脉冲 |
| BAT_ADC | P0.31 / AIN7 | 电池分压采样 |
| BAT_ADC_EN | P0.09 | 采样分压网络使能 |

### 3.2 IP5306 寄存器

| 寄存器 | bit | 含义 |
| --- | --- | --- |
| 0x70 | bit3 | 1 = charging |
| 0x71 | bit3 | 1 = full |

### 3.3 电池电压分压

- R6 = 100kΩ
- R8 = 100kΩ
- 分压比 = 2
- `VBAT = ADC电压 × 2`

## 4. IP5306 驱动设计

### 4.1 为什么做成 out-of-tree Zephyr 驱动

Zephyr 中没有现成的 IP5306 驱动，所以按 Zephyr 标准方式新增：

- `dts/bindings/mfd/injoinic,ip5306.yaml`：devicetree binding。
- `drivers/ip5306/ip5306.c`：驱动源码。
- `include/drivers/ip5306.h`：对外 API。
- `drivers/ip5306/Kconfig`：驱动配置选项。

这样后续如果工程要复用 IP5306，只需要拷贝驱动目录和 devicetree 节点即可。

### 4.2 Devicetree 节点

在 `app.overlay` 中增加：

```dts
&i2c0 {
	status = "okay";
	clock-frequency = <100000>;
	pinctrl-0 = <&i2c0_default>;
	pinctrl-1 = <&i2c0_sleep>;
	pinctrl-names = "default", "sleep";

	ip5306: ip5306@75 {
		compatible = "injoinic,ip5306";
		reg = <0x75>;
		wakeup-gpios = <&gpio0 22 GPIO_ACTIVE_LOW>;
		keepalive-period-ms = <8000>;
		keepalive-pulse-ms = <500>;
	};
};
```

使用 devicetree 而不是硬编码引脚，是为了符合 Zephyr 开发标准，方便后续改板。

### 4.3 驱动接口

```c
int ip5306_init(void);
int ip5306_get_status(struct ip5306_status *status);
```

- `ip5306_init()`：检查 I2C/GPIO 设备是否就绪，并启动硬件 keepalive。
- `ip5306_get_status()`：读取 0x70/0x71，解析 charging/full。

## 5. 硬件 keepalive 设计

### 5.1 为什么需要 keepalive

IP5306 在轻载或待机时可能自动关断输出。为了让系统在低功耗状态下仍然保持供电，需要周期性给 IP5306 的 WAKEUP 脚一个有效脉冲。

要求：

- 每 8000ms 一个脉冲。
- 脉冲宽度 500ms。
- P0.22 是 active low，所以有效电平为低。

### 5.2 为什么使用 RTC2 中断 + GPIO 控制

如果使用 `k_work_delayable` 线程定时器：

- 低功耗 suspended 时，软件定时器可能不可靠。
- 会增加 CPU 唤醒次数，不利于省电。
- 无法保证在深度低功耗下继续产生脉冲。

所以选择 RTC2 中断 + GPIO 控制：

```text
RTC2 COMPARE[0] 事件
   → PPI → GPIOTE Toggle → P0.22 拉低（脉冲开始）

RTC2 COMPARE[1] 事件
   → PPI → GPIOTE Toggle → P0.22 拉高（脉冲结束）

RTC2 COMPARE[1] 事件
   → PPI → RTC2 CLEAR（计数器清零，自动开始下一个周期）
```

RTC2 是低功耗外设，在 CPU 睡眠时仍然运行；PPI 直接连接 RTC 事件到 GPIOTE 任务，CPU 完全不参与 keepalive 脉冲产生。

### 5.3 实现方法

1. 通过 `nrfx_gpiote` 分配 1 个 GPIOTE 通道，配置为 Toggle 输出任务。
2. 配置 RTC2：
   - 32.768kHz。
   - CC0 = 8000ms tick。
   - CC1 = 8000ms + 500ms tick。
3. 配置 PPI：
   - COMPARE[0] → GPIOTE Toggle。
   - COMPARE[1] → GPIOTE Toggle。
   - COMPARE[1] → RTC CLEAR。
4. 启动 RTC2。

这样即使主线程进入低功耗，RTC2 中断 + GPIO 也会自动产生 keepalive 脉冲，CPU 不需要醒来。

## 6. 电池电压采样与 SOC

### 6.1 ADC 采样流程

1. 拉高 BAT_ADC_EN（P0.09），使能分压网络。
2. 等待分压网络稳定。
3. 通过 ADC 读取 AIN7。
4. 拉低 BAT_ADC_EN，节省功耗。
5. 电压 = ADC 毫伏值 × 2。

### 6.2 ADC 配置

```dts
&adc {
	status = "okay";

	channel@0 {
		reg = <0>;
		zephyr,gain = "ADC_GAIN_1_4";
		zephyr,reference = "ADC_REF_INTERNAL";
		zephyr,input-positive = <NRF_ADC_AIN7>;
		zephyr,acquisition-time = <ADC_ACQ_TIME_DEFAULT>;
	};
};
```

### 6.3 SOC 计算

- 3300mV → 0%
- 4200mV → 100%
- 中间线性换算，再四舍五入到 10% 档位。

```c
soc = ((voltage_mv - 3300) * 100 + 450) / 900;
soc = ((soc + 5) / 10) * 10;
```

## 7. battery_module 设计

### 7.1 功能

`battery_module.c` 负责：

1. 初始化 IP5306。
2. 每 8 秒读取 IP5306 charging/full。
3. 每 8 秒采样电池电压。
4. 计算 SOC。
5. 发布 `battery_event` 到 app_event_manager。

### 7.2 为什么使用事件发布

项目已经使用 CAF `app_event_manager` 作为事件总线。通过发布 `battery_event`，后续显示模块、低电量告警、日志模块都可以订阅，而不需要修改 battery_module。

---

## 8. 与 CAF Power Manager 的协同

### 8.1 低功耗进入

- 空闲超时后，CAF Power Manager 发送 `power_down_event`。
- `power_state_logger` 打印 `enter low power`。
- 系统进入 suspended，不进入 System OFF。

### 8.2 低功耗下 keepalive

- IP5306 keepalive 由 RTC2 硬件产生。
- 即使 CPU 进入低功耗，RTC2 仍运行，keepalive 脉冲不会停止。

### 8.3 按键唤醒

- 按键按下产生 `button_event`。
- `button_wake` 判断当前是否 suspended。
- suspended → 发送 `wake_up_event`。
- 非 suspended → 发送 `keep_alive_event`。
- `power_state_logger` 收到 `wake_up_event` 后打印 `exit low power`。

## 10. 关键决策总结

| 决策 | 原因 |
| --- | --- |
| 使用 out-of-tree 驱动 | Zephyr 无现成 IP5306 驱动，按标准方式扩展 |
| 使用 devicetree 配置引脚 | 符合 Zephyr 标准，便于换板 |
| 使用 I2C 读取状态 | IP5306 状态寄存器在 I2C 上 |
| keepalive 使用 RTC2 中断 + GPIO 控制 | 低功耗下仍能硬件输出脉冲，不依赖 CPU |
| keepalive 每 8s、500ms、active low | 符合 IP5306 要求和硬件连接 |
| 使用 ADC 采样 BAT_ADC | 硬件已有分压网络 |
| SOC 按 10% 档位 | 满足显示/告警粒度要求 |
| 使用 battery_event 发布 | 与 CAF 事件总线一致，方便后续扩展 |
| 使用 CAF Power Manager | 统一管理低功耗状态和唤醒事件流 |

## 11. 验证方法

1. 编译通过。
2. 检查 devicetree 中有 `compatible = "injoinic,ip5306"` 节点。
3. I2C 地址为 0x75。
4. 用示波器/逻辑分析仪观察 P0.22：
   - 每 8000ms 出现一个约 500ms 低电平脉冲。
5. 查看 RTT 日志：
   - `[battery] charging=... full=...`
   - `[battery] vbat=... mV soc=...%`
6. 等待空闲超时：
   - 打印 `enter low power`
7. 按键：
   - 打印 `exit low power`
   - 按键日志正常输出
8. 轻载待机时确认 IP5306 不自动关断。

## 12. 注意事项

1. keepalive 使用 RTC2 中断 + GPIO 控制，占用 1 个 GPIOTE 通道和 3 个 PPI 通道。
2. 当前 GPIOTE 通道由编码器 A/B（2 个）和矩阵 6 行唤醒中断（6 个）使用，共 8/8，已刚好用满。
3. BAT_ADC_EN 对应 P0.09，属于 NFC1 引脚，必须依赖 `&uicr { nfct-pins-as-gpios; };` 释放后才能作为 GPIO。
4. 当前 keepalive 已使用硬件定时；低功耗时 battery_module 的周期任务会挂起，唤醒后再恢复。
