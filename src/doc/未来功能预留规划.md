| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |

| 状态 | 规划（未实现） |
| 目标 | 为灯带、LCD 显示屏、时间显示等功能**预留接口与资源**，避免后续冲突或资源不够 |

## 1. 预留目标

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| WS2812B 灯带（17 颗） | 后续 | 每键一灯 RGB，灯效 |
| ST7789V LCD 显示屏 | 后续 | 显示电量 / 模式 / 充放电 / 时间 |
| 时间显示 | 后续 | 需 RTC + 主机时间同步（TimeSync） |
| 2.4G 模式 | 硬件不支持 | 仅保留枚举，不实现 |

> 本文档只做**规划**，当前 BLE 实现阶段不写灯带/LCD 代码，但**接口与资源分配从现在起预留**。

## 3. 接口预留设计（当前实现即遵守）

### 3.1 事件接口（已预留，零改动）

| 事件 | 未来消费者 | 现状 |
| --- | --- | --- |
| `battery_event` {level, state} | LCD 电量/充放电图标 | ✅ 已有 |
| `mode_event` | LCD 模式显示、灯带配色 | ✅ 已有 |
| `hid_led_event` | 指示灯 / LCD 提示 | ✅ 已有 |
| `timesync_event`（预留） | LCD 时间显示 | 📋 需新增（参考工程 protocol_module） |
| `theme_rgb_event`（预留） | 灯带主题 | 📋 需新增（参考工程） |

### 3.2 调度/传输层（已预留）

- `hid_scheduler` 与传输无关，未来 **BLE/USB/2.4G 共用**，灯带/LCD 不占用其资源；
- `hid_report_to_send/sent` 事件接口稳定，新增传输模块只需"多一个消费者"。

### 3.3 电源预留

- 灯带峰值电流：17 × 20mA = 340mA（全亮），需 IP5306 BOOST 供电（已设 BOOST always-on ✅）；
- LCD 背光 PWM 独立于主灯，避免背光闪烁影响灯效。

## 4. 资源风险与对策

| 风险 | 对策 |
| --- | --- |
| **RAM 不足**（当前 40992B / 256KB，15.6%） | LCD framebuffer 用 LVGL 分块渲染（参考工程 LV_Z_VDB_SIZE=20）；BLE 栈 +15~20KB 需评估堆 |
| **Flash 不足**（当前 94380B / 1MB，9%） | 灯带/LCD 驱动 + LVGL 约 +100KB，余量充足 |
| **GPIOTE 通道耗尽**（nRF52 8 通道） | IP5306 用 2 个（SET/CLR）+ CAF buttons PORT 事件；灯带用 SPI（非 GPIOTE）✅ 不冲突 |
| **外设冲突** | SPI0（灯带）/ SPI3（LCD）/ PWM0（背光）均为独立外设，与现有 I2C1/QDEC0/ADC 无冲突 |
| **线程/调度** | LVGL 需专用 workqueue（参考 LV_Z_RUN_LVGL_ON_WORKQUEUE），与 HID 调度层隔离 |
| **2.4G 硬件不支持** | 保留 `KEYBOARD_MODE_2_4G` 枚举与响应矩阵位，不注册传输 |

---

## 5. 建议实施顺序（后续）

1. **BLE HID**（当前阶段）→ 三模中两模可用；
2. **LCD 显示屏**：ST7789V + LVGL → 电量/模式/充放电显示（复用 battery/mode 事件）；
3. **灯带**：WS2812B 灯效（theme_rgb_event 预留接口）；
4. **时间显示**：TimeSync（主机同步 → RTC → LCD 时钟）；
5. **2.4G**：硬件升级后接入（接口已预留）。

---

## 6. 与当前 BLE 实现的关系

- BLE 实现**不占用**灯带/LCD 预留的引脚与外设（见 §2.2）；
- BLE 只新增一个 `hid_report_to_send_event` 消费者，不改变事件接口；
- 未来 LCD/灯带订阅的 `battery_event`/`mode_event`/`hid_led_event` 均为现有事件，**无需改造已有模块**。
